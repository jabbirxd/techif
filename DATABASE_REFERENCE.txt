============================================================
OVERALL DATABASE PURPOSE
============================================================
This database supports a Laravel-based eCommerce system for:
- product catalog management
- category and brand organization
- color and product variant management
- customer wishlist and cart operations
- checkout and order processing
- admin settings and content management
- user authentication and role-based access

The project uses Laravel Eloquent models and migrations, plus Livewire components for interactive frontend/cart/checkout logic.

============================================================
DATABASE RELATIONSHIP SUMMARY
============================================================
The database is designed around a simple eCommerce flow:

Users
  -> Carts
  -> Wishlists
  -> Orders

Products
  -> Product Images
  -> Product Colors
  -> Cart items
  -> Order items

Categories
  -> Products
  -> Brands

Colors
  -> Product Colors

Orders
  -> Order Items

This relationship design is necessary because:
- users need ownership over carts, wishlists, and orders
- products need category and media/variant support
- carts are temporary while orders are permanent
- order_items make a single order capable of containing many products
- product_colors avoid duplicate product rows for each color
- product_images avoid storing multiple images inside the products table

============================================================
HOW TO EXPLAIN THIS DATABASE IN VIVA
============================================================
You can speak about the project database in this structure:

1. Start with the main goal:
   This database is designed for an eCommerce system where users can browse products, add them to cart or wishlist, place orders, and admins can manage catalog and settings.

2. Explain the most important tables:
   - users: stores customers and admins
   - products: stores the main product catalog
   - catagories: organizes products by category

   - product_images: stores product images
   - product_colors: stores product variants by color

   - products table stores product core data
   - product_images handles multiple images
   - product_colors handles variants and stock by color
   - carts and orders are separated because carts are temporary and orders are final records
   - order_items separate the order header from the detailed purchased products

5. Explain the advantages of the design:
   - easier maintenance
   - cleaner data organization
   - better scalability
   - simpler future extensions
   - better support for transactions and reporting

6. Explain possible future improvements:

   - add coupon and shipping tables
   - add product reviews and ratings

7. End with a strong summary:
   In short, this database is a practical and modular eCommerce database that supports product catalog management, user interaction, cart handling, order processing, and admin control.
